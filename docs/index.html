What narrows it fastest

How the error bar is computed clustering, variance components, sources

The estimate is the share of correct answers over all runs. The error bar treats questions, not runs, as the independent units: runs of the same question share its difficulty, so they are not new evidence. The standard error is cluster-robust by question, with the small-sample factor N/(N−1) and a t critical value with N−1 degrees of freedom (Miller, 2024, "Adding Error Bars to Evals", arXiv:2411.00640).

SE² = N/(N−1) · Σᵢ (cᵢ − kᵢ·p̂)² / (Σᵢ kᵢ)² interval = p̂ ± t₀.₉₇₅,N−1 · SE cᵢ = correct runs on question i, kᵢ = runs on question i, p̂ = Σcᵢ / Σkᵢ

Naive interval (shown for contrast): a Wilson interval on all N×K answers as if they were independent. It is too narrow whenever questions differ in difficulty.

Questions or repeats. A one-way analysis of variance splits the noise into σ²q, how much questions differ in difficulty, and σ²w, how much the same question flips between runs. The variance of the estimate at a design of N questions × K runs is σ²q/N + σ²w/(N·K): extra runs shrink only the second term, extra questions shrink both. The chart uses this formula with your estimated components. With one run per question the two cannot be separated.

Var(p̂) ≈ σ²q / N + σ²w / (N·K) σ²w = MS_within, σ²q = max(0, (MS_between − MS_within) / K)

Two models: for each question, B's accuracy minus A's; the interval is a t interval on those N differences. Pairing by question removes question difficulty from the comparison.

Why questions beat repeats

An accuracy estimate varies for two reasons: questions differ in difficulty (between-question variance, σ²q), and the same question flips between runs (within-question variance, σ²w). The variance of the estimate at design (N, K) is σ²q/N + σ²w/(N·K). Extra runs only shrink the second term; extra questions shrink both. For these models the first term dominates, so repeats are a poor buy:

Clustering uncertainty by question is not this project's idea: it is the recommendation of Miller (2024), “Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations” (arXiv:2411.00640), and this project follows it. What is added here is the empirical coverage check on real runs, the Bayesian comparison, the budget guidance, and this playground. All numbers are precomputed from the saved runs — the page makes no live model calls.
